# M1.11 Text / Font Rendering Contract

Status: UNVERIFIED
Date: 2026-09-16
Base checkpoint: M1.10 GameCanvas E2E DEVICE-PASS
Base lock commit: `dc5f70867cef636797a36d52e7b45bafcfad0c74`
Device: original Anbernic RG35XX

## CURRENT_SYMPTOM

The standalone RG35XX path now proves display, raw input, MobilePlatform dispatch, Canvas rendering, framebuffer presentation, and GameCanvas rendering/flush on real hardware. Text/font rendering remains outside the proven boundary. Earlier M1.9 work intentionally avoided `drawString()` because the pinned FreeJ2ME AWT-backed font/Graphics2D path is not valid in the RG35XX headless graphics mode.

## HISTORY_FOUND

Locked real-device checkpoints that must remain unchanged:
- M1.6 display -> SDL1/fbcon -> LCD: DEVICE-PASS
- M1.7 raw `/dev/input/js0`: DEVICE-PASS
- M1.8 JNI/dispatch -> MobilePlatform: DEVICE-PASS
- M1.9E framebuffer -> SDL1/fbcon -> LCD: DEVICE-PASS
- M1.9F Canvas input/render -> LCD: DEVICE-PASS
- M1.10 GameCanvas input/render/flush -> LCD: DEVICE-PASS

M1.9F-r6 previously exposed a shutdown NPE in `PlatformGraphics.drawString()` when the FreeJ2ME termination screen attempted text rendering with no AWT Graphics2D object. M1.9F/M1.10 acceptance harnesses therefore skip that AWT termination screen. That is evidence of the remaining text boundary, not a reason to reopen the locked primitive raster path.

## PREVIOUS_FIX

No text renderer has yet been promoted to DEVICE-PASS. Existing headless patches only establish PlatformFont sizing/state and primitive raster graphics needed by Canvas/GameCanvas checkpoints.

## PREVIOUS_EVIDENCE_LEVEL

Text/font rendering: UNVERIFIED as an end-to-end physical LCD capability.

## REGRESSION_RISK

HIGH if font work changes the locked display/input/GameCanvas paths or reintroduces GNU Classpath GTK/AWT peer dependencies. M1.11 must isolate text as the only primary variable.

## MINIMAL_PROPOSED_CHANGE

Create a bounded headless text-rendering acceptance probe on top of the locked M1.10 platform. The first M1.11 implementation must:
- preserve M1.6-M1.10 source/binary boundaries unless an explicit text-only adapter is required;
- avoid GTK/AWT peers and avoid requiring a live `Graphics2D` object;
- exercise MIDP `Font` + `Graphics.drawString()`/`drawSubstring()` through a deterministic software-raster path;
- present through the already locked M1.10 frontbuffer -> M1.9E SDL1/fbcon path;
- use a small ASCII test set first; Unicode/Vietnamese glyph coverage is a later checkpoint and must not be bundled into the first text proof;
- make no audio/media changes;
- make no image/sprite changes;
- keep JamVM and glibj immutable;
- fail closed if the pinned FreeJ2ME source layout/anchors differ.

## EXPECTED_DEVICE_TEST

A successful M1.11 device checkpoint must show on the physical RG35XX LCD:
1. the already-proven primitive background/reference geometry;
2. clearly readable deterministic ASCII text rendered by the MIDP text API, not by shell/SDL overlay;
3. at least two MIDP font size/style state changes if supported by the isolated software path;
4. text remains correctly positioned after `Graphics.translate()`/clip state used by the locked headless graphics implementation;
5. normal bounded exit with no hard reset;
6. JamVM/glibj before/after hashes unchanged;
7. existing display and input paths show no regression.

BUILD-PASS does not imply DEVICE-PASS. Human visual confirmation on the real RG35XX remains mandatory.

## Out of scope for M1.11 first checkpoint

- audio/media
- arbitrary commercial JAR compatibility
- Unicode/Vietnamese/CJK completeness
- image/sprite/tiled-layer compatibility
- performance optimization
- full platform stability

`FULL_PLATFORM_STABLE` remains `NO`.
