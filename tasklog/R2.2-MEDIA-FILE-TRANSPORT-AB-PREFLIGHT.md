## Miyoo reference findings used only as architecture evidence

Both reviewed Miyoo FreeJ2ME implementations avoid shipping whole media blobs through a Java-to-native pipe. They persist media to a file and pass a path/handle to a native audio layer. R2.2 adopts only that file-backed ownership idea; it does not import SDL_mixer/JNI audio-device ownership.

## Scope lock

R2.2 changes only MIDI registration transport:

1. Java streams MIDI InputStream to `/mnt/mmc/CFW/java/cache/freej2me-media/` in 4 KiB chunks.
2. Java sends a small UTF-8 path command (`OP_REGISTER_MIDI_FILE`).
3. Native validates the path, loads the file, and registers bytes into the existing media cache.
4. Existing mixer, TSF worker, ring, audio callback and timing remain unchanged.
5. Tone and PCM remain on the previous transport for this A/B.

Explicitly unchanged: video, NoMask, font, PNG compatibility, dynamic logical view, transparency, JamVM L, GNU Classpath, worker-ring sizing, TSF rate, output rate, worker chunk, lifecycle ownership.
