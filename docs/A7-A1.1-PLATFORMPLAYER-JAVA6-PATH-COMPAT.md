# A7-A1.1 — PlatformPlayer Java-6 path compatibility owner

## CURRENT_INTEGRATION_FAILURE

Original RG35XX direct A7 evidence reaches the accepted A7 launcher and loads `libaudio.so`, but WAV player construction fails before `SdlMixerManager.init()` with:

`java.lang.NoClassDefFoundError: java/nio/file/Paths`

The failing call is in canonical `PlatformPlayer.sdlWavPlayer` directory preparation. Because WAV fails before native audio initialization, MIDI is not exercised by the parent A7 test.

## AWEIGIT_CANONICAL_BEHAVIOR

Pinned Aweigit commit: `ca11dfe8ea1cc273d92460f9a83bbf192023fa63`.

`PlatformPlayer.sdlPlayer` and `PlatformPlayer.sdlWavPlayer` both prepare `./rms/<suitename>` with:

`Files.createDirectories(Paths.get(rmsPath));`

The directory is then used only as a cache location for the temporary MIDI/WAV file passed to `SdlMixerManager`.

## HISTORY_FOUND

A3 already uses a disposable Java-6 compatibility source view instead of modifying the pinned canonical gitlink. In that view, canonical `MIDletLoader` Java-7 NIO/zipfs usage is translated to Java-6 `JarFile`/`JarEntry` while preserving the intended resource-loading behavior.

Therefore a runtime-compatibility rewrite in the disposable staged source is an established project mechanism and is distinct from changing the pinned Aweigit source.

## CURRENT_DIVERGENCE

The A7 media path was not exercised during A3-A6 non-audio acceptance, so the two `PlatformPlayer` Java-7 directory-creation calls escaped the existing Java-6 compatibility staging audit.

This is not evidence of an SDL1_mixer backend failure and not evidence of a Player/MMAPI state-machine failure.
